1. Executive Summary & Core Objective

This document details the production architecture for an event-driven, dual-path AI Agent system designed to power a personal portfolio and developer workflow within Google Gemini API Free Tier limits (15 RPM / 1M TPM / 1.5K RPD):

  • Path A: Public Visitor Assistant (Web UI): Sub-300ms read-only conversational assistant answering visitor inquiries about skills, projects, and bio with zero SQL latency and native typo tolerance.
  • Path B: Admin Developer Agent (Local CLI): Autonomous tool-augmented coding and database management agent with Human-in-the-Loop (HITL) approval gates.

3. Step-by-Step Implementation Blueprint

  1. Server Boot & In-Memory Pre-fetching: Backend server (FastAPI/Next.js) queries Supabase on startup once, formatting public tables into a structured RAM string (PORTFOLIO_CACHE).
  2. Zero-Tool Visitor Chat (1-Turn): Connect visitor questions directly to client.interactions.create with system_instruction=PORTFOLIO_CACHE and stream=True. Zero SQL execution and zero tool turns.
  3. Admin Mutation Agent (2-Turn with HITL): Tool declarations define file edits and DB updates. The local Python runtime intercepts function_call, presents diffs to the admin, prompts for confirmation, and returns function_result.
  4. Event-Driven Cache Invalidation: Admin updates automatically invoke refresh_portfolio_cache(), keeping visitor data instantly synchronized.
  5. Tiered Rate-Limit Guardrails: Client-side session limit (10 msgs max), IP throttling (1 req/3s), compact system prompt (<2k tokens), and Flash model selection (gemini-3.8-flash).
